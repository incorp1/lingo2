


# Задание для GLM 5.3 Flash: несколько изучаемых языков в Lingo Cards


> Исходный проект: Lingo Cards v3.19.16. Документ подготовлен по карте проекта и исходникам. При подготовке задания приложение не изменялось.
>
> Для первого норвежского языка выбран **норвежский букмол — Bokmål (`nb`)**. Это именно язык обучения, а не перевод интерфейса.


## 1. Цель и ограничения


Доработай приложенный **Lingo Cards v3.19.16**, чтобы пользователь мог независимо изучать английский и норвежский, переключаясь через **Настройки → Обучение → Язык изучения**.


Должны сохраняться данные и прогресс обоих языков, включая незавершённые циклы обучения. **Полная резервная копия должна содержать все языки**, независимо от выбранного в момент экспорта.


Перед изменениями прочитай `AGENTS.md` и соответствующие разделы `PROJECT_MAP.md`. Карта — навигатор; окончательный источник истины — текущий код.


Обязательные ограничения:


- Сохрани существующее статическое PWA на HTML/CSS/JavaScript, размещаемое на Cloudflare и устанавливаемое на iPhone.
- Не добавляй React, сборщик, сервер, авторизацию или новую БД.
- Не переписывай приложение целиком и не меняй дизайн вне необходимых элементов.
- Сохрани работу Safari/iOS 15, офлайн-обучение, текущие AI-провайдеры и пользовательские ключи.
- Не меняй математические алгоритмы SM-2/FSRS и смысл существующих оценок.
- Не редактируй исторический `app-original.html`.
- Не заменяй реальные функции заглушками.
- Не ограничивай изменение одним переключателем: язык должен учитываться во всех учебных сценариях.


Сначала кратко перечисли затрагиваемые файлы, схему данных и порядок проверки. Затем выполняй изменение по этапам ниже.


## 2. Пользовательское поведение


Добавь в начало раздела «Обучение» настройку «Язык изучения»:


- Английский — `en`.
- Норвежский (букмол) — `nb`.


По умолчанию выбран английский. После обновления все существующие данные остаются английскими, без изменений содержимого и прогресса.


При переключении меняются:


- доступные колоды и карточки;
- учебная очередь и счётчики;
- статистика и серия дней;
- список слов для практики;
- история и незавершённая практика;
- язык генерации слов, примеров, текстов и вопросов;
- язык озвучивания изучаемого материала.


Запоминай выбор языка после закрытия приложения, перезагрузки и восстановления полной копии. Запоминай выбранную колоду отдельно для каждого языка.


Первое открытие норвежского показывает честное пустое состояние с работающим созданием/импортом колоды. **Не копируй английские карточки и не запускай английский seed для норвежского.** Пользователь может добавить норвежские слова вручную, списком, импортом и существующими AI-функциями.


Показывай текущий изучаемый язык в существующей учебной области, чтобы пользователь понимал контекст. Не добавляй отдельную сложную систему профилей в интерфейс.


Язык интерфейса `settings.language` остаётся независимым: `ru`, `uk`, `en`. Выбор норвежского не должен переводить интерфейс или менять существующие переводы карточек.


Для минимального законченного изменения остальные настройки, включая параметры планировщика, AI-провайдера, ключ, тему, режимы карточки и скорость речи, остаются **общими**. Отдельные настройки алгоритма для каждого языка в эту задачу не входят.


## 3. Схема данных: один полный набор сущностей и языковая метаинформация


Используй следующую архитектуру, не создавая отдельную IndexedDB на язык и не подменяя `state` урезанным состоянием.


### 3.1. Реестр изучаемых языков


Добавь единый реестр, например `window.LCLanguages`, содержащий:


- код языка;
- ключ локализованного названия;
- название для AI-промптов;
- локаль TTS;
- признак поддержки существующим словарным API;
- при необходимости отдельные коды для существующих переводческих сервисов.


Начальные записи: `en` и `nb`; для TTS — `en-US` и `nb-NO`. Не используй `no` как основной идентификатор профиля: если конкретный сервис требует `no`, преобразуй код только в его адаптере.


Добавление следующего языка не должно требовать копирования веток английского/норвежского по всему приложению.


Если реестр вынесен в новый JS-файл, подключи его до потребителей — в том числе `ai.js` и `backup.js` — и включи в Service Worker.


### 3.2. Владение сущностями


- `state.decks` и `state.cards` всегда содержат данные **всех** языков.
- Добавь `deck.learningLanguage`.
- Язык карточки определяется через её колоду. Не дублируй его в карточке без необходимости.
- ID существующих колод и карточек не меняются; новые ID уникальны во всём приложении.
- Создание колоды использует явно переданный либо активный язык.
- Карточку нельзя сохранить в несуществующую колоду или случайно перенести в другой язык.
- Перенос между колодами разрешён внутри одного языка. Перевод колоды/карточки в другой язык в эту задачу не входит.


### 3.3. Языковые профили метаинформации


Добавь:


```js
state.activeLearningLanguage
state.languageProfiles[languageCode]
```


Каждый профиль содержит:


- `activeDeckId`;
- `history`;
- `streak`;
- `sessionReviewedIds`;
- `practiceDraft`;
- при необходимости небольшой `studyResume` для восстановления текущей карточки и учебного контекста.


Существующие `state.studyCycles` можно оставить общим объектом по глобально уникальным ID карточек. Не очищай его при смене языка. При использовании проверяй принадлежность карточки нужному языку.


`settings.practiceHistory` на этом этапе можно оставить общим массивом, но каждой записи добавь `learningLanguage`. Фильтруй его при показе и при операциях. Сохрани действующую политику ограничения истории **отдельно для каждого языка**, чтобы практика норвежского не вытесняла историю английского.


Добавь `learningLanguage` к новым `reviewEvents`. При миграции старых событий определяй язык через карточку/колоду; старые события исходного одноязычного состояния относятся к английскому.


### 3.4. Один источник истины


Введи явные помощники, например:


- `getActiveLanguageProfile()`;
- `getLearningLanguageForDeck(deckId)`;
- `getLearningLanguageForCard(card)`;
- `getActiveLanguageDecks()`;
- `getActiveLanguageCards()`.


Переведи чтение и запись прежних одиночных полей `state.history`, `state.streak`, `state.activeDeckId`, `state.sessionReviewedIds`, `state.practiceDraft` на языковые профили.


Не оставляй две независимо изменяемые копии этих значений. Если нужны временные адаптеры совместимости, они должны обращаться к единственному каноническому месту хранения, а не поддерживаться ручным копированием в разных обработчиках.


**Критически важно:** фильтрация интерфейса не должна изменять глобальные массивы. Нельзя присвоить `state.cards = state.cards.filter(...)` ради переключения: механизм delta-сохранения может принять отсутствующие карточки за удалённые.


## 4. Миграция и IndexedDB


Текущая БД — `lingo-cards`, версия 3; `STORAGE_KEY = "lingo-cards-v1"`. Сохрани эти идентификаторы. Версию IndexedDB повышай только при реальном изменении stores/indexes, а не ради номера релиза.


Сделай явную версию новой модели данных и идемпотентную миграцию:


1. Загрузить старое состояние и связанные данные.
2. Назначить существующим колодам `learningLanguage: "en"`.
3. Перенести старые одиночные поля в `languageProfiles.en`.
4. Сохранить существующий `practiceDraft`, историю практики и review events как английские.
5. Создать пустой профиль `nb` либо создавать его безопасно при первом выборе.
6. Установить активный язык `en`.
7. Сохранить результат через существующий защищённый механизм записи.


Не меняй даты повторений, интервалы, оценки, `reps`, `lapses`, `fsrs`, `difficultyCache`, приостановку карточек, `linkedCardId`, содержимое `info` и других полей. Не восстанавливай историческую статистику приблизительно, если её точные значения уже есть.


Повторный запуск миграции не должен дублировать колоды, заново переносить статистику или обнулять норвежский профиль. Прерывание записи не должно оставлять наполовину мигрированное состояние. При ошибке — сообщение и возможность повторить запуск, а не инициализация пустой БД.


Проверь все способы материализации состояния в `storage.js`, особенно:


- `stateMetaFrom`;
- `readStructuredState`;
- `appStateFromRecords`;
- `readAppSnapshot`;
- `snapshotBaseline` и построение delta;
- `initializeAppState`;
- `replaceAppSnapshot`;
- recovery snapshots;
- `appendDeck`;
- обработку внешнего изменения состояния между вкладками.


Новые поля необходимо провести через **обычное сохранение, полную замену, экспортный snapshot и восстановление**. Изменения только `normalizeLoadedState` недостаточно.


Сохрани dirty-флаги, ревизии, транзакции, rollback, retries и защиту от устаревшей записи. Не используй прямую очистку stores.


Не допускай записи старой вкладкой устаревшего одноязычного состояния поверх уже мигрированных данных: проверь существующую revision-защиту и поведение вкладки после внешнего изменения; при несовместимой схеме требуется безопасное прекращение записи и обновление страницы.


## 5. Переключение языка как согласованная операция


Реализуй одну асинхронную функцию переключения; не разбрасывай изменение активного языка по обработчикам.


Порядок:


1. Проверить код; повторный выбор текущего языка — no-op.
2. Защититься от параллельных переключений и повторных нажатий.
3. Завершить либо безопасно дождаться уже начатого сохранения оценки/редактора. Не переключать контекст посреди commit.
4. Обработать несохранённые редакторы существующим механизмом сохранения/подтверждения; не молча терять введённый текст.
5. Остановить языковые асинхронные операции и сделать их результаты неактуальными.
6. Зафиксировать черновики настроек, текущий цикл и практику исходного языка; дождаться `saveAndFlush()`.
7. Сохранить новый активный язык и профиль через защищённую запись.
8. Только после успеха сбросить временную сессию и Undo, очистить старые выделения, открытый список чужой колоды, кэши виртуальных списков и состояние модалок.
9. Восстановить учебный контекст выбранного языка, обновить счётчики, селекторы, статистику, подписи и таймеры.


При ошибке записи переключатель и интерфейс остаются на прежнем языке. Не показывай успешное переключение до подтверждения сохранения.


Останови TTS, устаревшие анимации/таймеры, перевод выделения, информацию о слове, генерацию практики, пакетное обновление примеров и массовое AI-заполнение.


Одного `AbortController` недостаточно: каждому языковому запросу сохраняй контекст языка и идентификатор поколения/операции. Перед применением ответа после `await` проверяй язык, сущность и актуальность операции. Это должно защищать и сценарий `en → nb → en`, когда старый английский ответ приходит после возвращения.


Уже подтверждённые успешные результаты пакетной операции не теряются; отменённые остатки не записываются в новый контекст.


## 6. Обучение, колоды и статистика


Проверь все обращения к `state.cards`, `state.decks` и старым одиночным полям в:


- `js/state.js`;
- `js/scheduler.js`;
- `js/study.js`;
- `js/decks.js`;
- `js/cards.js`;
- `js/stats.js`;
- `js/ai-practice.js`;
- `js/app-shell.js`.


Не делай слепую глобальную замену: операции полного экспорта и глобального хранения должны продолжать видеть все языки.


Особое внимание:


- Сейчас `getDeckCards(null)` возвращает все карточки. Учебный вариант «Все колоды» после изменения означает **все колоды активного языка**.
- В `refillStudyQueue` есть обход `state.cards`, если колода не задана.
- `startSession` может очищать `sessionReviewedIds`; возвращение к языку не должно случайно стирать список для практики «последняя сессия».
- `nextDueAt`, `hasNewInDeck`, `deckStats`, обновление по таймерам и пустые состояния должны учитывать активный язык.
- Поиск, фильтры, выбор всех строк, массовое удаление/перенос, обновление примеров и проверка дубликатов работают только в правильном языковом контексте.
- Для английской и норвежской колоды допустимы одинаковые названия и одинаково написанные слова.
- Статистика и heatmap показывают активный язык. Обучение норвежскому не увеличивает английский streak.
- Обычные селекторы колод показывают активный язык; подписи полной копии и глобального удаления явно относятся ко всем языкам.


Сохрани механику вариантов `word/sentence × english/local` и применение худшей оценки после завершения цикла.


Для минимизации риска **сохрани внутреннее legacy-значение `english` как обозначение стороны изучаемого языка**, но обнови пользовательские подписи: для `nb` эта сторона должна называться норвежской. Не переименовывай значения формата без необходимости. Проверь `studyCardFronts`, `normalizeStudyCycles`, санитайзеры, меню режимов и кнопку направления.


При возврате к языку восстанавливай доступную текущую карточку/незавершённый цикл. Не сохраняй весь объект `session` с временными полями: достаточно валидируемого указателя и существующих `studyCycles`; очередь пересчитывается по текущему времени. Если карточка удалена или больше недоступна — безопасно продолжай со следующей подходящей.


## 7. AI, словарь, практика и перевод


В текущем коде английский зашит в нескольких независимых местах. Обязательно обработай:


- `ai.js`: `userPrompt`, `generate`, `generateWordInfo`, `WORD_INFO_SYSTEM_PROMPT`, `WORD_INFO_PROMPT_PREFIX`, `WORD_INFO_PROMPT_SUFFIX`, `batchExamplesPrompt`, `generateExamplesBatch`, `quickLookup`, `quickTranslate`, `callDictionary`.
- `js/ai-practice.js`: `generateCard`, промпты уровней, `practiceGenerate`, `practiceCheck`, история и черновики.
- `js/decks.js`: `enrichBulkCard`.
- `js/study.js`: `requestWordInfo`, пакетное обновление примеров.
- `js/selection.js`: перевод и добавление выделенного слова.


Раздели явные понятия:


- **изучаемый/исходный язык** — английский или Norwegian Bokmål;
- **язык перевода и объяснения** — существующий язык интерфейса.


Сейчас `aiTargetLangName()` фактически использует язык интерфейса. Не превращай его в функцию изучаемого языка: это перевернёт направление переводов. Существующее поле `aiTargetLang` тоже нельзя использовать как переключатель языка обучения.


Для норвежского:


- слова, примеры, тексты, вопросы и образцы ответов — на Bokmål;
- переводы и пояснения — на языке интерфейса;
- проверка грамматики оценивает норвежский, а не английский;
- информация о слове объясняет норвежское употребление, а не выдаёт английские шаблоны;
- существующие сохранённые тексты не перегенерируются автоматически при переключении.


### Словарный API


Сейчас `DICT_URL` ведёт на `dictionaryapi.dev/.../entries/en/`. **Не заменяй `en` на `nb` без подтверждённой поддержки API.**


В английском оставь текущий словарь. Для `nb` не вызывай английский endpoint; используй уже имеющийся переводчик, а в AI-режиме — AI. Если словарный режим не может предоставить транскрипцию/пример, оставь соответствующие поля пустыми с понятным поведением, а не подставляй английские сведения или выдуманные значения.


Не добавляй новый внешний сервис ради этой задачи. Передавай правильный код исходного языка существующим переводчикам; специфические соответствия `nb/no` изолируй в адаптерах. Ошибка сервиса должна давать понятную ошибку, а не ложный успешный перевод.


Для любых кэшей языковых результатов ключ должен учитывать хотя бы исходный язык, язык перевода и текст; при необходимости — модель и остальные параметры результата.


### История и черновики практики


Сохраняй отдельно для каждого языка текст, вопросы, введённые ответы, feedback, выбранные слова, уровень, формат и этап практики. Проверь, что закрытие старой модалки после переключения не перезаписывает черновик нового языка.


## 8. Озвучивание и норвежские символы


Сейчас `detectLang()` в `js/app-shell.js` считает почти любой латинский текст английским. Для норвежского это неправильно.


Расширь `speak` явным параметром языка. На учебных вызовах передавай язык конкретного текста:


- изучаемое слово/пример — локаль языка колоды;
- перевод — локаль языка перевода;
- при обратной карточке язык определяется ролью текста, а не расположением на экране.


Не полагайся на наличие букв `æ/ø/å`: слово `hus` тоже норвежское. При отсутствии подходящего системного голоса не выбирай принудительно английский голос; обработай отсутствие возможности озвучивания корректно. Проверь загрузку списка голосов через `voiceschanged`, если добавляется явный выбор голоса.


Сохрани скорость речи и автоозвучивание. Смена языка отменяет текущую речь.


В `js/selection.js` есть широкий диапазон букв, но дополнительные проверки `/[A-Za-z]/` отбрасывают слова, состоящие только из специальных букв. Проверь все три места: геометрию слов, извлечение слова и подтверждение выделения.


Тестовые значения: `å`, `ø`, `øy`, `å gå`, `blåbær`, `lærer`, `hus`, `gift`. Они должны нормально сохраняться, искаться, выделяться и передаваться на перевод. Не удаляй диакритику и не превращай `å` в `a`. Сохрани iOS touch-fallback, безопасное экранирование и работу многословных выражений.


## 9. Полная резервная копия, импорт колод и восстановление


### 9.1. Новый формат полной копии


Текущий `LCBackup.CONFIG.format` — 2. Введи **формат 3**, поскольку меняется структура сохраняемого прогресса. Сохрани чтение форматов 1, 2 и поддерживаемых legacy-вариантов.


Формат 3 должен содержать:


- все колоды и карточки всех языков;
- активный язык;
- все языковые профили;
- `studyCycles`;
- review events всех языков;
- историю практики всех языков;
- черновик практики каждого языка;
- общие настройки и существующую семантику включения AI-ключа.


Не оставляй старый одиночный `snapshot.practiceDraft` вторым источником истины: при чтении старого формата мигрируй его в английский профиль. Для формата 3 черновики живут в профилях.


Обнови санитайзеры `backup.js`: новые поля иначе будут молча удаляться. Проверь ограничения количества истории/черновиков: они не должны обрезать другие языки только из-за глобального лимита, введённого для одного языка.


Сделай round-trip: `snapshot → buildFullExport → parse → replaceAppSnapshot → reload`, с сопоставлением содержимого и прогресса **обоих** языков.


Неизвестный формат, неподдерживаемый язык или противоречивые связи в новой многоязычной копии должны давать понятную ошибку **до записи**, без тихого превращения данных в английские. Присваивание отсутствующего языка `en` допустимо для известных старых одноязычных форматов, но не как универсальное исправление повреждённой новой копии.


Не переназначай карточку из повреждённой норвежской колоды в первую английскую колоду. Проверь ссылки `deckId`, `linkedCardId`, `activeDeckId`, выбранные слова практики и `studyResume` в рамках языка.


### 9.2. Семантика полного восстановления


Сохрани текущую семантику **полной замены приложения**, а не неявного слияния:


- новая копия восстанавливает все содержащиеся в ней языки;
- старая полная копия восстанавливает английские данные и пустой норвежский профиль;
- если до импорта уже есть норвежские данные, предупреждение явно сообщает, что полное восстановление заменит также их;
- отмена ничего не изменяет;
- recovery snapshot позволяет откатить замену целиком, включая все языки.


### 9.3. Экспорт и импорт отдельной колоды


Добавь язык в экспорт колоды, сохранив его прежний смысл: **контент без учебного прогресса**.


- Новая копия колоды импортируется в записанный в ней язык, а не молча в активный.
- При несовпадении с активным языком покажи целевой язык в подтверждении.
- Для старой копии колоды без языковой метки предложи выбрать язык импорта; по умолчанию английский для обратной совместимости.
- ID импортированных сущностей новые, без коллизий с данными любого языка.
- Полная копия и копия колоды остаются разными типами; не смешивай их обработчики.


Проведи новые поля через `buildDeckExport`, `sanitizeDeckContent`, UI импорта и `LCStorage.appendDeck`.


**Замечание по текущему коду:** `sanitizeDeckContent` сохраняет `info`, но показанная реализация `storage.js/appendDeck` не переносит `cardInput.info` в создаваемую карточку. При доработке импорта сохрани и это поле; не ограничивай round-trip только новым языковым кодом.


Обычный экспорт, быстрая копия и Share Sheet должны использовать один полный многоязычный формат.


## 10. Сброс и удаление


Зафиксируй понятную область действия:


- «Сбросить прогресс текущего языка» сбрасывает только учебный прогресс активного языка, его статистику, события повторений, незавершённые циклы, sessionReviewedIds и учебный resume/черновик. Содержимое карточек и завершённая история практики сохраняются согласно выбранной и явно описанной семантике текущего сброса. Другой язык не меняется.
- «Удалить все данные приложения» остаётся глобальной операцией и явно предупреждает об удалении **всех языков**.
- Удаление колоды и массовые операции не затрагивают чужие языки.
- Восстановление последнего опасного изменения возвращает полный согласованный snapshot.


При сбросе текущего языка нельзя передавать `reviewEvents: []` для всего приложения, как сейчас делает глобальный `resetProgress`: нужно сохранить события остальных языков.


Не добавляй отдельную кнопку удаления языка — она не требуется.

## 12. Обязательные проверки


Добавь поведенческие тесты на `node:test`, используя существующие `fake-indexeddb` и `happy-dom`. Одних проверок исходников регулярными выражениями недостаточно.

5. Создать английскую и норвежскую колоды, в том числе с одинаковыми названиями/словами; прогресс независим.

9. Ошибка сохранения переключения оставляет прежний язык; быстрые повторные переключения не создают гонку.
10. Поздний AI-ответ/таймер после `en → nb` и `en → nb → en` не меняет неактуальный контекст.

12. Сброс норвежского не меняет английские карточки, события, историю и черновики.


### Резервные копии


13. Полный экспорт при активном `nb` содержит оба языка, включая их черновики, статистику и review events.
14. Импорт этой копии в пустую БД восстанавливает оба языка и активный выбор.
15. Импорт старой полной копии работает по описанной семантике полной замены; recovery возвращает прежние данные обоих языков.
16. Экспорт/импорт норвежской колоды сохраняет язык и весь поддерживаемый контент, включая `info`, но не учебный прогресс.
17. Старая колода без языка проходит явный выбор назначения.
18. Неизвестный язык/формат, повреждённые связи и отменённый импорт не меняют БД.
19. Отдельно проверить обычный экспорт, быструю копию и Share Sheet.


### Языковые функции


20. Промпты норвежского требуют Bokmål, английские продолжают требовать английский; язык перевода не перепутан с изучаемым.
