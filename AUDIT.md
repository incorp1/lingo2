## Протокол работы (читать перед продолжением в любом новом чате)

Этот файл — единственный источник правды о состоянии исправлений. Любой агент, получивший репозиторий, должен:

1. Открыть `AUDIT.md` и найти первый дефект со статусом `- [ ]` (не исправлен).
2. Исправить **только этот один дефект**, следуя разделам «Необходимые изменения» и «Способ проверки».
3. Запустить `npm test` — все тесты должны проходить.
4. Поставить `- [x]` в заголовке дефекта и заполнить строку `Статус:` (кем/когда, хеш коммита оставить пустым до коммита).
5. Сделать **отдельный коммит**, содержащий изменения кода/тестов этого дефекта **и** обновлённый `AUDIT.md`.
   Формат сообщения коммита: `fix(audit-N): краткое описание`, где N — номер дефекта.
6. Выполнить `git push origin feat/multiple-learning-languages`.
7. Перейти к следующему невыполненному пункту и повторить.

Правила:
- Один дефект — один коммит. Не объединять исправления нескольких дефектов.
- Не менять нумерацию и формулировки дефектов; только статус и, при необходимости, раздел «Примечания по исправлению».
- Если дефект после проверки признан ложным срабатыванием — отметить `- [x]` и в `Статус:` указать `ложное срабатывание` с обоснованием.
- Прогресс определяется исключительно чекбоксами в этом файле, а не историей чата.

## - [x] Дефект 1. Миграция языковой модели не выполняется в рантайме (критично)

**Статус:** исправлен. Коммит: см. `fix(audit-1)` в ветке `feat/multiple-learning-languages`

**Файл и участок**
- `js/state.js:781` — `function normalizeLanguageModel(loaded)`
- `js/state.js:891` — `normalizeLoadedState(loaded)`
- `js/state.js:929`, `js/state.js:1037`, `js/state.js:1074` — точки загрузки состояния

**Описание дефекта**
`normalizeLanguageModel()` — единственное место, где легаси-состояние переводится в формат `languageProfiles` / `activeLearningLanguage` / `dataModelVersion`. Поиск по репозиторию показывает, что она вызывается **только из тестов** (`tests/language-model-migration.test.js`, `tests/language-study-isolation.test.js`) и ни разу из кода приложения. `normalizeLoadedState()` нормализует settings, decks, cards, studyCycles, но `normalizeLanguageModel(loaded)` не вызывает, хотя именно она — общий вход для всех путей загрузки (`adoptLoadedState`, восстановление и `initializeAppState`).

**Последствия**
- Пользователь со старыми данными после обновления получает состояние без `languageProfiles` и без корректного `activeLearningLanguage`.
- `decksForLanguage` / `cardsForLanguage` / `isDeckInActiveLanguage` сравнивают язык колоды с `state.activeLearningLanguage`, который может быть `undefined` — существующие колоды и карточки могут исчезнуть из интерфейса.
- `stateMetaFrom()` (`storage.js:238-240`) сохранит `dataModelVersion: 1`, `activeLearningLanguage: null`, `languageProfiles: null`, закрепив некорректный формат в IndexedDB.
- Тесты миграции зелёные, но проверяют функцию напрямую, а не реальный путь загрузки.

**Необходимые изменения**
Вызвать `normalizeLanguageModel(loaded)` внутри `normalizeLoadedState()` (после нормализации `decks`/`cards`, до `syncActiveLanguageProfile`), сохранив идемпотентность повторных вызовов.

**Способ проверки**
Тест, подающий легаси-снапшот в реальный путь загрузки (`normalizeLoadedState` / `initializeAppState`) и проверяющий наличие `languageProfiles`, корректного `activeLearningLanguage`, `dataModelVersion` и видимость старых колод. Вручную — открыть приложение с легаси-данными в IndexedDB и убедиться, что колоды остались.

**Примечания по исправлению**
В `normalizeLoadedState()` (`js/state.js`) добавлен вызов `normalizeLanguageModel(loaded)` после нормализации `decks`/`cards` и перед `return loaded`. Функция идемпотентна, поэтому повторные загрузки безопасны. Проверка: `npm test` — 223/223 проходят.

## - [x] Дефект 2. `wipeAll()` создаёт состояние без языковой модели

**Статус:** исправлен. Коммит: см. `fix(audit-2)` в ветке `feat/multiple-learning-languages`

**Примечания по исправлению**
В `wipeAll()` (`js/import-export.js`) литерал `emptyState` дополнен полями `dataModelVersion`, `activeLearningLanguage` и `languageProfiles` (по всем кодам из реестра языков), как в конструкторе начального состояния в `js/state.js`. Проверка: `npm test` — 223/223 проходят.

**Файл и участок**
- `js/import-export.js:164-173` — литерал `emptyState` в `wipeAll()`

**Описание дефекта**
`emptyState` содержит `decks`, `cards`, `activeDeckId`, `settings`, `history`, `streak`, `sessionReviewedIds`, `studyCycles`, но не содержит `activeLearningLanguage`, `languageProfiles` и `dataModelVersion`. Канонический пустой state в `js/state.js:1047-1048` эти поля задаёт явно.

**Последствия**
После полного удаления данных состояние теряет языковую модель. С учётом дефекта 1 состояние может остаться без профилей и после перезагрузки: переключение языка, изоляция колод и запись в `meta` работают на `null`-значениях.

**Необходимые изменения**
Формировать `emptyState` из общего конструктора пустого состояния (того же, что в `js/state.js:1047-1048`), чтобы `activeLearningLanguage`, `languageProfiles` и `dataModelVersion` всегда присутствовали.

**Способ проверки**
Тест на `wipeAll()`: после вызова состояние содержит профили всех языков из `languageCodes()`, валидный `activeLearningLanguage` и актуальный `dataModelVersion`. Вручную — полное удаление, перезагрузка, переключение языка.

**Примечания по исправлению**

## - [x] Дефект 3. Обновление карточек в `js/study.js` идёт по глобальному `state.cards`

**Статус:** исправлен. Коммит: см. `fix(audit-3)` в ветке `feat/multiple-learning-languages`

**Примечания по исправлению**
Три выборки в `js/study.js` переведены на языковые селекторы: `cardsForStudyExampleRefresh()` и `refreshSelectedExamples()` используют `activeCards()`, `refreshDeckExamples()` — `activeCards(deckId)` (он же проверяет `isDeckInActiveLanguage`). Проверка: `npm test` — 223/223 проходят.

- `js/study.js:981` — `const cards = state.cards.filter(card => card.deckId === deckId);`

**Описание дефекта**
В остальных местах модуля используются языковые селекторы (`activeDecks()` — `js/study.js:16`, `activeCards(deckId)` — `js/study.js:124`, `activeCards()` — `js/scheduler.js:625`). Перечисленные три выборки обходят селекторы и работают по всему массиву карточек, включая карточки неактивного языка.

**Способ проверки**
Тест изоляции: состояние с карточками двух языков, запуск массовой операции при активном `nb` — карточки `en` не изменены. Вручную — переключить язык и выполнить массовое обновление примеров.

## - [ ] Дефект 4. `activeLearningLanguageCode()` объявлена в модуле практики, но используется модулями, загружаемыми раньше

**Статус:** не исправлен. Коммит: —

**Файл и участок**
- `js/ai-practice.js:18-22` — определение `activeLearningLanguageCode()`
- Потребители: `js/study.js` (2 вызова), `js/selection.js:512-513` (2 вызова), `js/decks.js` (1 вызов)
- `index.html:1389-1396` — `js/study.js` и `js/decks.js` подключаются **до** `js/ai-practice.js`

**Описание дефекта**
Общий языковой хелпер живёт в модуле AI-практики, а не в `js/state.js`/`languages.js`, при этом его используют модули обучения, колод и выделения. **Последствия**
Хрупкая зависимость: любое раннее выполнение (обработчик до загрузки `js/ai-practice.js`, изменение порядка `<script>` или ленивая загрузка модуля практики) приведёт к `ReferenceError` в пути обучения и работы с колодами. Также нарушается разделение ответственности из `PROJECT_MAP.md`.

**Необходимые изменения**
Перенести `activeLearningLanguageCode()` в общий слой (`js/state.js` или `languages.js`, рядом с `normalizeLearningLanguage`), оставив в `js/ai-practice.js` только использование.

**Способ проверки**
После переноса `grep` не находит определения хелпера в `js/ai-practice.js`; тест, загружающий `js/study.js` без `js/ai-practice.js`, успешно вычисляет код активного языка.
