## Как продолжить работу (читать первым делом)

Этот файл — единственный источник правды о ходе исправлений. Он самодостаточен:
репозиторий можно передать в другой чат на любой стадии, и работа продолжится без контекста.

Протокол для исполнителя:

1. Прочитать `AGENTS.md`, `PROJECT_MAP.md` и этот файл.
2. Найти в «Таблице прогресса» первый дефект со статусом `pending` (наименьший номер).
3. Открыть его раздел ниже, выполнить исправление строго по описанию «Что изменить».
4. Запустить `npm test` (ожидается минимум 203 пройденных теста, 0 упавших) и `git diff --check`.
   При необходимости добавить/обновить тест — он указан в поле «Проверка» дефекта.
5. В этом файле: поставить `[x]` в заголовке дефекта, изменить статус в таблице прогресса
   на `done`, записать в поле «Результат» фактический итог (что изменено, результат тестов).
6. Сделать **отдельный коммит** только для этого дефекта, включая правку `AUDIT.md`:
   `git commit -m "fix(audit): <номер> <краткое описание>"`.
7. Сразу отправить ветку: `git push origin feat/multiple-learning-languages`,
   затем сверить `git rev-parse HEAD` с `git ls-remote origin refs/heads/feat/multiple-learning-languages`.
8. Только после совпадения хешей переходить к следующему дефекту.

Правила: один дефект — один коммит; не смешивать несколько дефектов в одном коммите;
не отправлять незавершённые изменения в `main`; не фиксировать ключи и секреты;
если исправление невозможно — поставить статус `blocked` и записать причину в «Результат».

     колоде активного языка, а не только по полю `learningLanguage`, чтобы корректно обработать
     legacy-события без метки.
- Проверка: новый тест в `tests/` — событие получает язык колоды; сброс прогресса при активном `nb`

  события удаляются по принадлежности `event.deckId` колодам активного языка, поле
