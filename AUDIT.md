## Дефекты

### 1. Блокирующий: пункт 6 отмечен `[x]`, но в тексте записано «Результат: не выполнено»

- Файл: `TASK_PLAN.md`, пункт 6 («Сделать AI, словарь и перевод языково-корректными»).
- Проблема: чек-бокс `[x]`, а строка результата — `Результат: не выполнено`. Само противоречие
  делает чек-лист недостоверным (по коду пункт фактически выполнен: `ai.js` получил
  `learningAiName`, `dictionaryCodeFor`, `translatorCodeFor`, `sourceLang` в промптах).
- Что изменить: привести результат пункта 6 в соответствие с фактическим состоянием —
  заменить `Результат: не выполнено` на фактический отчёт (какие тесты и какие функции покрыты),
  как это сделано в остальных пунктах.

### 2. Баг: озвучивание текста практики игнорирует язык обучения

- Файл: `js/ai-practice.js:879`.
- Код: `$("#practiceTtsBtn").onclick = () => speak(p.text.replace(/\*\*/g, ""));`
- Проблема: вызов `speak` без `lang`, поэтому срабатывает эвристика `detectLang(text)`. Норвежский
  текст практики без специфичных символов будет озвучен английским/иным голосом. Это нарушает
  пункт 8 плана («учебные вызовы определяют язык по роли текста»): все остальные учебные вызовы
  (`js/study.js:280`, `js/study.js:534`, `js/selection.js:478`) уже передают `learningSpeechLocale()`.
- Что изменить: `speak(p.text.replace(/\*\*/g, ""), { lang: learningSpeechLocale() })`.
  Если у сессии практики сохранён `practiceState.learningLanguage`, передавать локаль именно этого
  языка, а не текущего активного (модалка может быть открыта из истории другого языка).

### 3. Баг: отсутствуют ключи локализации `language.learning.en` / `language.learning.nb`

- Файлы: `languages.js:14,23` (объявляют `i18nKey: "language.learning.en"` / `"language.learning.nb"`),
  `i18n/ru.js`, `i18n/uk.js`, `i18n/en.js` — ключей нет; присутствуют только
  `language.name.en` / `language.name.nb`.
- Проблема: `learningLanguageLabel()` в `js/learning-language.js` при отсутствии перевода
  возвращает `language.aiName`, т.е. в интерфейсе на русском/украинском пользователь увидит
  «English» и «Norwegian Bokmål» вместо «Английский»/«Норвежский». Подписи в `<select id="setLearningLanguage">`
  и в `[data-learning-language-label]` не локализованы, что противоречит пункту 8
  («новые строки и динамические подписи во всех ru/uk/en»).
- Что изменить: добавить `language.learning.en` и `language.learning.nb` во все три словаря
  (`ru`, `uk`, `en`), либо изменить `languages.js` на `i18nKey: "language.name.<code>"`,
  чтобы использовать уже существующие ключи. Предпочтительно второе — меньше дублирования.
- Дополнительно: `i18n/uk.js` содержит языковые ключи в блоке строк ~123–128, тогда как в
  `ru.js` / `en.js` они находятся в районе ~604–610; стоит выровнять расположение, чтобы
  избежать случайного дублирования ключей в одном объекте.

### 4. Баг: `savePracticeToHistory()` пишет запись истории без `learningLanguage`

- Файл: `js/ai-practice.js:1242–1260`.
- Проблема: функция добавляет элемент в `state.settings.practiceHistory` без поля `learningLanguage`,
  тогда как `addPracticeHistory()` (строки ~1066–1078) это поле проставляет. По правилу
  `practiceHistoryLanguageOf()` запись без поля считается записью языка по умолчанию (`en`).
  Значит, сессия практики, сохранённая этим путём при активном `nb`, попадёт в английскую историю
  и не будет видна/удаляема в норвежском профиле. Нарушение пункта 7
  («История получает learningLanguage … все операции показа/удаления фильтруются»).
- Что изменить: добавить `learningLanguage: practiceState.learningLanguage || activeLearningLanguageCode()`
  в создаваемую запись; либо удалить дублирующую функцию, если она не используется —
  сейчас `savePracticeToHistory` не вызывается ни из одного файла (`grep` даёт только объявление),
  то есть это ещё и мёртвый код, дублирующий `addPracticeHistory`.

### 5. Недоработка: `PRACTICE_HISTORY_MAX` в `savePracticeToHistory` обрезает историю всех языков

- Файл: `js/ai-practice.js:1255–1258`.
- Проблема: обрезка `state.settings.practiceHistory.splice(PRACTICE_HISTORY_MAX)` выполняется по
  общему списку без фильтра по языку, в отличие от корректной реализации в
  `trimPracticeHistory()` (строки ~1044–1056), которая считает лимит отдельно по языку.
  При активном использовании одного языка записи другого языка будут вытеснены.
- Что изменить: использовать общий помощник обрезки с языковым фильтром
  (переиспользовать логику `trimPracticeHistory`), а не прямой `splice` по всему массиву.

### 6. Баг: `recordReviewEvent()` не записывает `learningLanguage` в событие

- Файл: `js/state.js:616–628`.
- Проблема: план (раздел «Схема данных», пункты 7 и 10) требует, чтобы `reviewEvents` получали
  `learningLanguage`. Событие формируется только с `cardId`, `deckId`, `grade`, `state`, `due`, `at`.
  При этом `js/import-export.js:128–129` при сбросе прогресса фильтрует события именно по
  `event.learningLanguage`, а `normalizeLearningLanguage(undefined)` возвращает `"en"`.
  Последствие: **сброс прогресса при активном `nb` удалит все накопленные реальные reviewEvents
  как «английские»**, а сброс при активном `en` не удалит норвежские события, если они
  когда-либо были записаны без поля. Это повреждение данных статистики/сложности.
- Что изменить: в `recordReviewEvent` добавить
  `learningLanguage: deckLearningLanguage(card.deckId)` (или `cardLearningLanguage(card)`).
  Дополнительно в `js/import-export.js` фильтровать события по принадлежности `event.deckId`
  колоде активного языка, а не только по полю `learningLanguage`, чтобы корректно обрабатывать
  legacy-события без метки.
- Замечание: `storage.js:506` проставляет `learningLanguage` только при импорте колоды
  (`appendDeck`), что не компенсирует отсутствие поля в обычном учебном потоке.

### 7. Недоработка: статистика по дням (`state.history`) остаётся зеркалом, а heatmap читает её напрямую

- Файлы: `js/stats.js:20–40`, `js/stats.js:338–348`.
- Проблема: карточные счётчики корректно ограничены `activeCards()`, но `reviewed`, retention и
  heatmap читают `state.history` — совместимое зеркало профиля. Пока зеркало синхронизировано
  через `syncActiveLanguageProfile`/`adoptLanguageProfile`, это работает, однако любой путь,
  который меняет `state.history` без последующего `syncActiveLanguageProfile` до `save()`,
  запишет данные в чужой профиль. План требовал, чтобы профили были «единственным каноническим
  местом хранения».
- Что изменить: читать и писать историю/streak через явный accessor профиля
  (например `activeLanguageProfile(state).history`), оставив `state.history` только как
  read-only совместимость, либо покрыть тестом сценарий «изменение history без явного sync».

### 9. Замечание: `SELECTION_HAS_LETTER` не покрывает не-латинские алфавиты

- Файл: `js/selection.js:9–15`.
- Текущий вид: `/[A-Za-zÀ-ÖØ-öø-ÿ]/` (а также `SELECTION_WORD_CHARS` / `SELECTION_WORD_SCAN`).
- Проблема: требование пункта 8 по норвежским `å/ø/æ` выполнено, регрессии нет. Но диапазон
  `À-ÖØ-öø-ÿ` не включает `ā/ș/ł/č` и кириллицу, поэтому выделение по удержанию не сработает,
  если в будущем добавится язык вне Latin-1 Supplement. Для текущей пары en/nb — не дефект,
  а ограничение расширяемости.
- Что изменить (по желанию): перейти на `\p{L}` с флагом `u`
  (`/\p{L}/u`, `/[\p{L}'’-]+/gu`), сохранив touch-fallback и экранирование.
